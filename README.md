# Balance & Progression Studio

Статическое веб-приложение (HTML/CSS/vanilla JS) для проверки баланса игры: импорт таблиц статов, расчёт урона и TTK, кривые прогрессии, проверка лута, экспорт в JSON/CSV. Сервер и база данных не нужны, всё хранится в `localStorage` браузера.

**Онлайн:** https://fuheshka.github.io/balance-progression-studio/

## Запуск локально

Вариант 1 — просто открыть `index.html` двойным кликом. Работает всё, кроме кнопок «Примеры» (браузер запрещает `fetch` с `file://`): файлы из `data/` в этом случае перетаскиваются в зону импорта вручную.

Вариант 2 — через локальный сервер (работает всё):

```bash
python3 -m http.server 8000
```

Потом открыть http://localhost:8000.

Тесты формул (Node.js 18+, без зависимостей):

```bash
node --test tests/
```

## Формулы

**Урон за удар**

```
урон      = max(attack − defense, attack × minRatio) × множитель
ожидаемый = урон × (1 + critChance × (critMult − 1))
удары     = ⌈hp / урон⌉
TTK       = (удары − 1) / attackSpeed        (первый удар в момент t = 0)
```

Почему так:
- `attack − defense` — классическая вычитающая формула. Её легко считать в уме, и она показывает, что броня сильнее против слабых атак.
- `attack × minRatio` (по умолчанию 10 %) — нижний порог урона. Без него рыцарь с защитой 20 неуязвим для крестьянина с атакой 6, и бой длится бесконечно.
- Криты учитываются как матожидание: шанс × добавка урона.
- TTK = (удары − 1) / скорость: первый удар наносится сразу, дальше — через интервал 1/attackSpeed. Поэтому TTK = 0 значит «убивает первым ударом».

**Прогрессия:** `XP до следующего уровня = round(base × L^power + linear × (L − 1))`.

**Лут:** сумма `chance` в каждой группе `group` = 100 % (сумма округляется до 1e-9, чтобы погасить погрешность float).

**Аудит:** каждый юнит дерётся с каждым, побеждает меньший ожидаемый TTK. Эффективность = доля побед ÷ (цена ÷ медианная цена). Относительно медианы эффективности: ≥ 1.3 — доминирует, ≤ 0.7 — бесполезен.

**Экономика:** `баланс_t = баланс_{t−1} + Σ источник·(1+рост)^{t−1} − Σ сток·(1+рост)^{t−1}`.

Ручная проверка формул на примерах — в [REPORT.md](REPORT.md) и в `tests/core.test.js`.

## Форматы данных

Юниты (CSV или JSON-массив / `{"units": [...]}`):

```csv
id,name,hp,attack,defense,cost,crit_chance,crit_mult,attack_speed
1,Мечник,120,25,10,100,0.1,1.5,1
```

Обязательные колонки: `id,name,hp,attack,defense,cost`. Необязательные: `crit_chance` (0–1), `crit_mult` (≥ 1, по умолчанию 1.5), `attack_speed` (ударов в секунду, по умолчанию 1).

Лут: `id,item,chance` обязательны, `group` и `rarity` — нет. `chance` в процентах.

Навыки: `{"nodes": [{"id": "a", "name": "…", "cost": 1, "requires": ["b"]}]}`.
