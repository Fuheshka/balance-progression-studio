# Balance Studio

Учебный проект по курсу «Нейросети в разработке игр». Это сайт без бэкенда, на котором можно загрузить таблицу юнитов и лута и посмотреть, что с балансом: сколько ударов нужно одному юниту, чтобы убить другого, как растёт опыт по уровням, сходятся ли шансы дропа в 100%. Данные хранятся в localStorage, сервер не нужен.

Сайт: https://fuheshka.github.io/balance-progression-studio/

## Как запустить

Можно просто открыть `index.html` в браузере. Работать будет всё, кроме кнопок с примерами: с адреса `file://` браузер не даёт читать соседние файлы. Тогда файлы из папки `data/` нужно перетащить в окно вручную.

Чтобы работало всё, лучше поднять локальный сервер:

```bash
python3 -m http.server 8000
```

и открыть http://localhost:8000.

Тесты формул запускаются через Node 18 или новее, ставить ничего не нужно:

```bash
node --test tests/
```

## Что внутри

Обязательная часть кейса:

1. Импорт. CSV (через запятую, точку с запятой или таб) и JSON, можно перетащить файл. Проверяются обязательные колонки, числа, пустые поля, отрицательные значения и повторы id. Если в файле ошибка, он не загружается, а вместо этого выводится список «строка, колонка, что не так». Можно загрузить только целые строки.
2. Таблица. Ячейки редактируются прямо на месте, строки и колонки можно добавлять и удалять. Всё сохраняется само, выгружается в CSV и JSON.
3. Урон и TTK. Выбираешь двух юнитов и видишь расчёт с подставленными числами, плюс матрицу «все против всех».
4. Прогрессия. Кривая опыта с тремя коэффициентами, таблица уровней и график.
5. Лут. Проверка, что в каждой группе шансы дают 100%, подсветка проблемных строк, нормализация, симуляция бросков и выгрузка результата.

Сверху сделал аудит баланса, симулятор экономики, дерево навыков, кнопку с DeepSeek, тёмную тему, мобильную вёрстку и горячие клавиши (список открывается по `?`).

## Ассистент

Работает через OpenRouter или напрямую через DeepSeek, сервис выбирается во вкладке «ассистент». Для OpenRouter нужен ключ с https://openrouter.ai/keys, список моделей подтягивается с OpenRouter: есть поиск и фильтр «только бесплатные», рядом видна цена за 1M токенов. Ключ хранится только в браузере.

## Формулы

Урон. Взял вычитание защиты из атаки: её легко проверить в уме, и сразу видно, что броня сильнее режет слабые удары. Но если защита больше атаки, урон становится нулевым и бой никогда не кончается, поэтому снизу его держит 10% от атаки.

```
урон      = max(атака − защита, атака × 0.1) × множитель
в среднем = урон × (1 + шанс_крита × (множитель_крита − 1))
ударов    = ⌈hp / урон⌉
TTK       = (ударов − 1) / ударов_в_секунду
```

Единица вычитается, потому что первый удар происходит сразу, в момент 0. Поэтому TTK = 0 значит, что цель умирает с одного удара.

Опыт до следующего уровня: `round(b × L^p + c × (L − 1))`, где L — текущий уровень.

Лут: в каждой группе (колонка `group`) сумма `chance` равна 100. Перед сравнением сумма округляется до 9 знаков, иначе из-за дробей в JS `0.1 + 64.1 + 35.8` выходит 99.99999999999999.

Аудит: каждый юнит дерётся с каждым один на один, побеждает тот, кто убьёт быстрее. Доля побед делится на относительную цену (цена юнита / медианная цена). Если результат в 1.3 раза выше медианного, юнит помечается как имба, если ниже 0.7 — как слабый.

Экономика: на каждом шаге баланс меняется на сумму источников минус сумму стоков, и каждая статья растёт на свой процент.

Ручная проверка формул на примерах лежит в [REPORT.md](REPORT.md), те же примеры есть в `tests/core.test.js`.

## Форматы

Юниты:

```csv
id,name,hp,attack,defense,cost,crit_chance,crit_mult,attack_speed
1,Мечник,120,25,10,100,0.1,1.5,1
```

Первые шесть колонок обязательны. `crit_chance` задаётся от 0 до 1, `crit_mult` по умолчанию 1.5, `attack_speed` — ударов в секунду, по умолчанию 1. JSON принимается в виде массива или `{"units": [...]}`.

Лут: обязательны `id,item,chance`, где `chance` в процентах. Колонки `group` и `rarity` можно не указывать.

Навыки: `{"nodes": [{"id": "a", "name": "...", "cost": 1, "requires": ["b"]}]}`.

## Тестовые файлы

В `data/` лежат:

- `units.csv` — 12 нормальных юнитов;
- `loot.csv` — 12 предметов в двух группах, обе ровно на 100%;
- `units_broken.csv` — 10 строк, в шести из них ошибки: текст вместо числа, повтор id, отрицательная защита, пустое имя, hp = 0, нет цены;
- `loot_broken.csv` — отрицательный и нулевой шанс, группы на 102% и 90%;
- `units.json` и `skills.json` — для проверки импорта JSON и дерева навыков.
